# Meridian Retail Bank — Enterprise AI Governance & Segregation of Duties (SoD) Architecture

An auditable, multi-agent governance pipeline designed for regulated banking environments (aligned with **SR 11-7** Model Risk Management and **EU AI Act** traceability requirements).

## 1. Core Architectural Controls

To prevent AI hallucinations and unauthorized state mutations in executive reporting, this system enforces strict **Banking Segregation of Duties (SoD)**:

- **Single-Mutator Data Steward (`Agent 0`)**: Deterministic rule engine and the **only** component permitted to write to or update the Master Workbook. Enforces mandatory `owner_confirmed == True` and non-empty `evidence_id` controls. Unverified records are isolated as `QUARANTINED_UNCONFIRMED` and logged to an immutable `audit_log`.
- **Read-Only Analytical Agents (`Agents 1, 2, 3`)**: Domain-specialized LLM analysts (**PMO Delivery**, **Business Analysis & Scope**, and **AI Governance & Risk**) operating on deep-copied, immutable snapshots. Prompt-level and schema-level guardrails strictly forbid fabrication, requiring `UNKNOWN` for missing or quarantined fields.
- **Human-in-the-Loop (HITL) Steering Committee Gate (`Orchestrator`)**: Compiles the final executive Steering Committee Pack by including only sections where `validated_by_owner == True`. Unvalidated domains are automatically redacted with `PENDING OWNER VALIDATION`.

## 3. Quickstart Guide

### Option A: Run the Python Prototype
1. Install the Google GenAI SDK:
   ```bash
   pip install google-genai
   ```
2. Set your Gemini API key as an environment variable:
   ```powershell
   \$env:GEMINI_API_KEY="YOUR_GEMINI_API_KEY"
   ```
3. Execute the governance pipeline:
   ```bash
   python meridian_governance_run.py
   ```

### Option B: Import the Visual Workflow in n8n
1. Open **n8n** (Cloud or self-hosted Community Edition).
2. Create a new blank workflow, click the **three dots (`...`)** in the top-right corner, and select **Import from File...**.
3. Select `meridian_n8n_workflow.json` and connect your Google Gemini API credentials to the three read-only analyst nodes.

## 4. Security & Production Notes
- **Credential Hygiene**: Always store API keys in environment variables (`GEMINI_API_KEY`) or an enterprise secrets manager—never commit live API keys to source control.
- **Auditability**: Every accept/reject decision generated by `Agent 0` records a UTC timestamp, actor ID, record ID, evidence reference, and rejection reason in `immutable_audit_trail`.
